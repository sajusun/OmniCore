# Ojais Wellness App Architecture & Data Flow Plan

Based on the full Figma wireframes, here is the complete breakdown of how the entire app connects together, where data flows, and how the "Insights" are generated from user actions.

## Overview of Data Flow
The app's core loop works like this:
**Set Goals (Profile) ➔ Scan Food (AI) ➔ Log Food (Diary) ➔ Generate Insights (Analytics)**

---

## 1. Onboarding & Profile (Goal Setting)
**Where it happens:** Splash Screen, Onboarding, Profile Settings.
**What happens:**
- The user signs up and enters their physical details (height, weight, age, activity level).
- The app calculates or the user sets their **Nutrition Goals** (Daily Target Calories, Carbohydrates, Protein, Fat).
**Database impact:**
- `users` table stores profile details.
- `nutrition_goals` table stores the target metrics for the user.

---

## 2. Food Scan & Analysis (Data Generation)
**Where it happens:** Scan Screen / Analyzing / Product Details.
**What happens:**
- The user takes a photo of their meal.
- The app calls the backend `POST /ojais/scan-food`.
- The `OjaisAIService` (OpenAI Vision) analyzes the image and returns:
  - Food Name & Nutritional Values (Calories, Macros).
  - **Ingredient Analysis:** Determines if the food is "Approved" (Healthy), "Neutral", or contains "Red Flags" (e.g., refined seed oils, high sugar).
  - A specific "Food Score" for that meal out of 100.
**Database impact:**
- Results are saved in the `food_scans` table for history.

---

## 3. Log Food (Connecting to the Diary)
**Where it happens:** "Log Food" Modal.
**What happens:**
- After viewing the scan results, the user clicks "Log".
- They select the **Meal Type** (Breakfast, Lunch, Dinner, Snack) and adjust the **Serving Size**.
- The app calls `POST /ojais/food-logs`.
**Database impact:**
- A new record is created in the `food_logs` table. This record links the user, the nutritional data, the food score, the date, and the meal type.

---

## 4. Daily Log Screen (The Diary)
**Where it happens:** Log Tab.
**What happens:**
- The app calls `GET /ojais/food-logs?date=YYYY-MM-DD`.
- The backend fetches all `food_logs` for that specific day.
- It groups the foods by Meal Type (Breakfast, Lunch, etc.).
- It sums up the total calories and macros consumed that day and compares them to the user's `nutrition_goals`.

---

## 5. Insights Dashboard (The Final Analytics)
**Where it happens:** Insights Tab.
**What happens:** 
This is where all the previous data comes together. To power this screen, we will need a dedicated Analytics Engine. We will create a new controller and endpoint: `GET /ojais/insights`.

The Insights endpoint will aggregate data from the `food_logs` table over a specified period (e.g., today, this week) and generate the following reports:

### A. Calories & Macros Overview
- **Calculation:** Sums up the total calories, carbs, protein, and fat from the `food_logs` for the day/week.
- **Comparison:** Compares the consumed totals against the `nutrition_goals` to calculate "Remaining" values and percentages for the UI ring charts.

### B. Food Quality Score & Detail
- **Calculation:** Looks at all the `food_logs` for the period.
- Averages the individual food scores to generate the **Average Food Score** (e.g., 25 out of 100).
- Counts how many logged items fall into the **Approved**, **Red Flags**, and **Neutral** categories.
- Generates the "All Foods" list detailing why certain foods were flagged (e.g., "Contains refined seed oils").

### C. Weekly Trends (Graphs)
- **Calculation:** Groups `food_logs` by day over the last 7 days.
- Calculates the total calories or average score for each day to format the data for the UI's Bar Charts and Line Graphs.

### D. Smart Recommendations (AI or Logic-based)
- **Calculation:** The backend will have a logic layer that analyzes the user's macro deficits. 
- Example Logic: If the user is consistently 30% below their protein goal, the backend generates a recommendation string: "Increase protein intake."

---

## Development Action Plan
To build this entire flow, here are the steps we need to take in the backend codebase:

1. **Phase 1: Nutrition Goals (Prerequisite)**
   - Ensure the `NutritionGoal` model and API endpoints exist so users can save their targets.
2. **Phase 2: Scanning (Completed/In Progress)**
   - Ensure `POST /ojais/scan-food` accurately returns nutritional data AND food quality analysis (Approved/Red Flag).
3. **Phase 3: The Diary (Log Food)**
   - Create the `food_logs` database table.
   - Build `POST /ojais/food-logs` (Save to diary).
   - Build `GET /ojais/food-logs` (Fetch daily diary with goal comparison).
4. **Phase 4: The Insights Engine**
   - Build a service class (e.g., `InsightService.php`) to handle complex data aggregation.
   - Build `GET /ojais/insights` endpoint to return the formatted data for the graphs, score details, and recommendations.
